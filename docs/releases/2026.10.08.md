# DOSBox Pure Standalone — 2026.10.08

This Windows x64 release completes differencing VHD milestone 5 for the
documented synthetic Windows scope. Opt-in packages keep the fixed/dynamic
parent immutable inside the executable and save a standard child VHD with its
package/disk identity binding.

## Changes

- Checkpoint dirty open children on a first-dirty deadline of at most five
  seconds, at the next safe frame, including paused frames. Continued writes
  do not postpone the deadline; publication duration depends on storage.
- Flush through the same checked publisher at BIOS reset/flush, reboot,
  poweroff, emulator exit/reset and disk/containing-drive unmount boundaries.
- Publish complete save ZIP generations through flushed staging, validated
  previous-generation retention and checked replacement. Recover complete
  validated generations after interrupted publication.
- Acquire a lifetime writer lock before loading/recovering a save. Renamed or
  identically repacked packages with the same identity contend for that lock.
- Capture matching machine, child and binding generations in bounded version-9
  save states and rewind, with preflight validation and rollback for reported
  deeper decoder failures. Ordinary packages keep version-8 state semantics.
- Reject unsupported legacy full-parent/unbound-child saves without changing
  them. Milestone 4 migration was discarded; no migration is implemented.
- Integrate the previously validated Codeberg upstream updates, including
  Pentium CMPXCHG8B, Unicode fixes and Nuked-SC55 integration. ROMs are not
  included; actual SC55-ROM/audio acceptance is separate.
- Update the VHD usage guide, examples, architecture, requirements and README.

The memory-backed archive path, immutable parents, child/binding identity,
ordinary archive behavior and separate persistent overlay remain intact.

## Validation

- `ReleaseGLCORE | x64`: zero warnings and errors.
- Synthetic runtime matrix: 64 case groups / 114 launches, including 35 core
  save-state/rewind cases; relevant archive and VHD identity regressions pass.
- Native and AddressSanitizer transaction suites: 121 checks each.
- VHD codec AddressSanitizer/Windows interoperability: 34,251 checks.
- Existing patch/utility regression: 132 checks; both Pentium guest probes pass.
- Two reviewed Process Monitor captures cover all 139 required synthetic,
  ordinary-archive and identity launches, with 12,260,786 attributed events.
  No physical fixture-member paths, immutable archive mutations, isolated TEMP
  activity, loose disk mutations or outside rename destinations were observed.
  Retained outside writes are NTFS metadata and NVIDIA timestamp paths; CSV
  path classification does not establish caller stacks or payload contents.

Exact builds, repeated-versus-distinct cases, failed preliminary reports,
capture recovery and limitations are recorded in the
[milestone 5 validation record](../differencing-vhd-persistence-validation.md).

## Upgrade and limits

Keep `makegame.exe` and the new clean `DOSBoxPureStandAlone.exe` together.
Previously generated game executables embed their own runtime; rebuild them
with the new template to adopt these fixes. Retain package/disk identity and
identical parent bytes when preserving an existing supported child/binding.
Do not delete existing saves to bypass an identity or format rejection.

Real Windows 98 boot/shutdown, filesystem/registry durability, gameplay and
performance remain milestone 6. Process termination tests and native flush
requests do not establish physical power-loss guarantees. ATA hooks have source
integration only in this default build, which disables hard-disk ATA emulation.
Disk-bearing states have a 512 MiB aggregate child snapshot cap and full-copy
memory/latency costs; callers must refresh buffers after child growth. POSIX and
opaque libretro storage URI transaction behavior are unqualified.

The release contains the clean runtime, self-contained .NET 8 package builder,
guides, examples and license notices. No game, operating-system image, ROM,
real save or generated game executable is included. Executables are unsigned.
`BUILD-INFO.txt` records source revisions and binary hashes; the downloadable
ZIP has a separate SHA-256 sidecar.
